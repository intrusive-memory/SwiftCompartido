# GitProject - Git Integration for SwiftCompartido

## Overview

GitProject adds native Git version control integration to SwiftCompartido, allowing screenplay projects to be versioned, collaborated on, and synchronized with remote repositories. This feature enables writers to track script revisions, collaborate with teams, and manage screenplay versions using industry-standard Git workflows.

## Phase 1: Core Git Operations ✅

### Completed Features

#### GitCredentialManager
- **Zero-configuration authentication** with automatic credential detection
- **5-level priority system**:
  1. SSH key detection (macOS only - `~/.ssh/id_ed25519`, `id_rsa`, `id_ecdsa`)
  2. Environment token detection (`GITHUB_TOKEN`, `GITLAB_TOKEN`)
  3. Git credential helper integration
  4. macOS Keychain integration
  5. Public repository (no auth)
- **Platform support**: iOS and macOS
- **Test coverage**: 90%+

#### GitProjectService
- **Actor-based service** for thread-safe Git operations
- **SwiftData integration** for repository and commit caching
- **Async/await API** with progress reporting
- **Core operations**:
  - `clone(remoteURL:localPath:progress:)` - Clone repositories with progress
  - `pull(repository:progress:)` - Fetch latest changes
  - `push(repository:progress:)` - Push commits to remote
  - `commit(repository:message:author:)` - Create commits
  - `status(repository:)` - Get repository status
- **Test coverage**: 90%+

#### SwiftData Models
- **GitRepositoryModel** - Repository metadata (path, remote, branch, LFS status)
- **GitCommitModel** - Commit history (SHA, message, author, timestamp)
- **Relationships**: Cascade delete for commits when repository is deleted

#### Dependencies
- **SwiftGitX 0.1.9** - Modern Swift wrapper for libgit2
- Automatic integration with system git configuration

## Phase 2: Git LFS Integration ✅

### Objectives

Enable Large File Storage (LFS) support for audio, video, and image files generated by AI services. SwiftCompartido generates significant multimedia content that should not be stored directly in Git.

### Components

#### LFS Detection & Configuration
- **`.gitattributes` parser** - Read and write LFS file patterns
- **Automatic LFS initialization** - Configure LFS when needed
- **File type detection** - Identify binary files that should use LFS
- **Size threshold configuration** - Configurable limits for LFS usage

#### LFS Operations
- **`installLFS()`** - Install Git LFS in repository
- **`trackPattern(_:)`** - Add file patterns to LFS tracking
- **`untrackPattern(_:)`** - Remove patterns from LFS tracking
- **`listTrackedPatterns()`** - Get all LFS-tracked patterns
- **`migrate()`** - Migrate existing large files to LFS

#### Default LFS Patterns
```gitattributes
*.mp3 filter=lfs diff=lfs merge=lfs -text
*.wav filter=lfs diff=lfs merge=lfs -text
*.m4a filter=lfs diff=lfs merge=lfs -text
*.mp4 filter=lfs diff=lfs merge=lfs -text
*.mov filter=lfs diff=lfs merge=lfs -text
*.png filter=lfs diff=lfs merge=lfs -text
*.jpg filter=lfs diff=lfs merge=lfs -text
*.jpeg filter=lfs diff=lfs merge=lfs -text
```

### User Workflows

#### Workflow 1: Initialize Git on Existing Project
1. User opens screenplay document
2. Taps "Enable Version Control" button
3. GitProjectSetupSheet appears (New Repository tab)
4. User optionally adds remote URL
5. Taps "Initialize Repository"
6. GitProjectConfigurationView becomes available

#### Workflow 2: Clone Remote Screenplay
1. User taps "Clone Project" in document picker
2. GitProjectSetupSheet appears (Clone Repository tab)
3. User enters GitHub/GitLab URL
4. GitCredentialManager auto-detects auth
5. User selects local save location
6. Taps "Clone Repository"
7. GitSyncProgressView shows progress
8. Document opens when clone completes

#### Workflow 3: Commit and Push Changes
1. User makes script edits
2. GitProjectConfigurationView shows "3 modified files"
3. User taps "Commit" button
4. Enters commit message
5. Taps "Commit and Push"
6. GitSyncProgressView shows progress
7. Success notification appears

#### Workflow 4: Pull Latest Changes
1. GitProjectConfigurationView shows "5 commits behind"
2. User taps "Sync" button
3. GitSyncProgressView shows fetch progress
4. Merge happens automatically
5. Document refreshes with new content

## Architecture Notes

### Thread Safety
- All Git operations use actors (`GitProjectService` is an `actor`)
- SwiftData operations wrapped in `@MainActor` where needed
- Background threads for file I/O and network operations

### Performance
- Lazy loading of commit history
- Pagination for large histories
- File reference storage for large files (LFS)
- Incremental status updates

### Platform Differences
- **macOS**: Full SSH key support, Keychain integration
- **iOS**: HTTPS-only, personal access tokens, app Keychain
- **Catalyst**: Hybrid support (SSH via macOS APIs)

### Error Recovery
- Automatic retry for network failures
- Rollback on commit failures
- Cleanup of partial clones
- Lock file detection and recovery
